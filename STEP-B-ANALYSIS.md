## 1. The verdict, on one page


**1. This is not a formatting project.** The pipeline has silently destroyed legally material content on
several documents — a deed's only footnote, fourteen of twenty-eight comment anchors, a contract's
closing bracket and terminal full stop, untranslated source-language text on the first page of a delivered
document — and in every case **every automatic check reported success**. Twenty-seven of the 168 recorded
findings are content losses. Six of them are the most serious grade the register has. **[measured]**

**2. The translation itself is not the problem and should not be touched.** Quality and terminology scored
9 on every one of the twelve graded documents; English-variant conformance scored 10 on all twelve. Whatever
we do, we must not spend Step B on translation quality. **[measured]**

**3. The single most useful sentence about why nothing was caught is no longer one sentence.** The strictest
and most-invoked check compares *bags of words* — no order, no punctuation, not even a count — and polices
only words that went missing, never words that appeared. But there are two more failures in the same family
and they are independent of it: the mandatory quality check never sets an exit code, so it reports success
to its own auditor on runs it has itself declared failed; and a delivered file that fails its own
integrity test produces a printed warning and a successful exit. **Anyone scoping this from the
bags-of-words sentence alone will under-build it — a mistake this project has already made once, in
writing.**

**4. There are eleven things we could do. Ten of them are worth doing, in an order, and none of them is a
rebuild.** The leap you asked for is available without one — because the most ambitious of the ten *is* the rebuild, done in slices small enough to merge one at a time. §2 argues that properly.

**5. Three things must be built before any fix can be believed, and only one of them was on the plan.**
The known one is the test harness. The two new ones came out of trying to refute the proposals: a rule
telling the operator that a check can be wrong about *what it is checking*, and a way for the tidy-up
script to declare what it changed. Without the first, making the checks discerning turns **eighteen** currently-silent defects into runs that can never finish. Without the second, the highest-value check in
the plan cannot be built at all.

**6. Cheapest-first and most-valuable-first point at two different places, and that is fine.** The cheapest
high-value work is one file: stop the code that puts English back from deleting things it does not
recognise. That closes four of the six worst content losses, changes no data format, and can be proved
correct by comparing bytes. The most valuable work is teaching the pipeline to check the delivered document
against the **original** rather than against notes the run wrote itself. Do the first, then the second.

**7. Speed does not appear in this list, and that is deliberate.** You set the rule — quality first, speed
never at its expense. The measured runtime problem is that the skill has **one gear**: about 25 minutes of
fixed ceremony whether the document is a two-page power of attorney or a 613-paragraph
contract. **[measured]** The only remedy that costs no quality is to let the skill be told what kind of job
it is doing, which is part of one of the ten options. Everything else that would make it faster — reading
fewer dictionaries, translating in bigger batches, thinning a check — is forbidden by your own rule, and the
evidence says all three would cost quality. There is no separate efficiency workstream: **fixing the
defects is the efficiency work**, because the gate cycles wasted on false alarms and the re-runs forced by
tool bugs *are* the time.

**8. Six of the findings need the claim fixed as well as the code.** A competent independent reader, working from the
published package and nothing else — no test result, no grade, no prior analysis — praised as the artefact's *strongest* feature the exact
layer this register shows is blind — and praised as *mature* the wording this register shows traps the
operator. Both readings are correct. That is not a disagreement to resolve; it is a measurement of how
convincingly the skill claims things it does not do, and a professional reader demonstrably acted on it.

## 4. How each branch is tested — THE METHOD


> **This section owns the test METHOD and nothing else.** *(Stated 2026-08-05.)* **§2 owns the order; §3 owns
> what counts as done for each option.** So: come here to find out *how* a branch of this kind is proved —
> byte comparison on a frozen intermediate, a synthetic fixture, a negative input, or a graded run — and go
> to §3's *Done when* line for the condition that has to be met. **Nothing here restates an acceptance
> criterion and nothing in §3 restates a method.**

**The trick that makes this affordable, and it is measured rather than assumed.** The expensive,
non-repeatable part of a run is the translation: a model, 20 to 50 minutes, and **linguistically about 40%
of paragraphs differ between two runs of the same document.** But **mechanically two runs are identical** —
that was measured on the project's only same-document repeat. **[measured]**

**So freeze the translated intermediate.** With the notes file frozen, the whole mechanical half — put the
English back, tidy up, reorder, auxiliary parts, repackage — becomes a **deterministic function**. Run the
scripts, compare the bytes. Seconds, repeatable, no model. **Those frozen intermediates already exist from
the July runs.**

**Two tiers, and the distinction is a confidentiality requirement, not a convenience.**

| tier | what | committable? | when it runs |
|---|---|---|---|
| **Synthetic** | Hand-built documents with no client text, in the repository | **YES** — and these are what runs on every change and what `git bisect` uses | every commit |
| **Real, frozen** | The frozen intermediates from the eleven corpus documents. They contain the **full client text** | **NEVER.** They live with the logs, outside the repository, and must be named in `.gitignore` **by path** before version control starts | before every merge |

> **A frozen intermediate is a new artefact class and it is the most content-rich file this project has ever
> produced.** The location rule already covers it in principle; it has never been applied to it in practice.
> Name it by path, not by extension.

**Negative test inputs are mandatory, not optional.** Nothing in the package can currently make a check fail,
so a test set of only-passing cases produces tests that pass because nothing is being tested. **One input per
check, built to violate that check's stated pass condition.**

**Why the graded run was the wrong instrument here, and this is measured rather than
argued.** An instruction branch of this kind only bites **when a check fires with the wrong
scope**. Cluster G is that set, and it is attested on **5 of the 11 corpus documents**, so a
single graded run reaches the situation slightly under half the time even before asking
whether it detects anything. And when it does reach it, the grader scores the *output* on 17
criteria, while what changed is **the operator's reasoning at a gate** — an axis the
register shows operators already mostly handling well. **So a graded run is not merely
expensive here; it measures the wrong variable.** That is the ground for moving it, not cost.

**What replaces it. Four instruments, each with a negative input proving it can fail:**

| | instrument | what it settles | model needed? |
|---|---|---|---|
| **1** | **`tools/reachability.py`** — §4.1's half one, which this document already assigns to branch 3 | Could the operator have **read** the rule at the moment it had to decide? Measures the steps at which a check can block and asserts the rule is readable at all of them | **no** |

For a rule *collision* this is not a proxy for the test; it **is** the test | **no** |
| **3** | **Execution** — fire the real gate on a synthetic input and read what it actually prints | Whether the edited wording is on the path the operator hits, rather than merely present in the file | **no** |

### 4.1 The prose-reachability probe — how and when, and it is NOT part of a fix

**Wouter, 2026-08-05: *"How and when do you want to do the probe? Is this part of the fix?"***

**No, it is not part of a fix. It is a MEASUREMENT**, and that settles where it goes: it produces no code and
no instruction edit, so it does not belong in a fix branch. It belongs with the measuring work.

**It splits into two halves that answer different questions, and only the second needs a run.**

**HALF ONE — static reachability. Now, no run, and it is the more actionable half.** Before measuring whether
an agent *obeys* an instruction, measure whether the instruction is **reachable at the step that needs it.**
This is a static analysis of the instruction layer and it costs nothing: for every mandatory rule, identify
the step at which the decision it governs is actually taken, and flag every rule whose governing statement
cannot legitimately be read until afterwards. **The register already holds one worked instance and it caused a
real wrong decision:** the date rule's governing statement lives in the Step 4 document, reading a step
document before arriving at it is forbidden, so the operator meets two misleading statements at Step 3,
decides, and meets the governing rule afterwards. **On one document it reasoned carefully, wrote a note, and
got it wrong — then reversed at Step 4.** That is a *reachability* defect, not a compliance defect, and no
behavioural experiment is needed to find more of them. **This half goes into Option 5's branch 3 as an
analysis step, because its output is a list of rules to move.**

**HALF TWO — the behavioural dose-response. At Step C, as a third arm.**

| | design |
|---|---|
| **Document** | **D09.** Already chosen for the two thinking-level arms, for the reason that makes it right here too: it contains **at least four discrete judgement calls with known-correct answers** that **no gate would catch** — the decimal separator, the heading-bold deviation, the first-*formatted*-fragment placement, and the footnote-anchor detection and repair. It has an existing baseline. **Avoid D11**, whose non-Latin appendix was reverse-engineered from that document, so its provenance is contaminated |
| **Manipulation** | One variable: **the mandatory step-file reads are suppressed** — headings only, no full read. Everything else held: same document, same harness version, same grader, same thinking level as the baseline |
| **Measure** | **The four known-answer judgement calls, NOT the grade.** This is not a preference; it is what the evidence requires. Quality and terminology score 9 on every graded document regardless, and the batch arm established the pattern: it *"did not translate worse. It policed the pipeline less."* A grade would miss exactly the thing being measured |
| **Position** | A **third arm** beside the `max` and `low` thinking arms on the same document. Same session cost, one more run. Against one baseline, each arm varies one thing: thinking level, thinking level, reading discipline |

**THE DESIGN'S OWN LIMIT, stated up front so nobody over-reads the result. This probe can CONFIRM but it
cannot REFUTE.** A single suppressed run showing large degradation is strong evidence that the reading
discipline pays. A single run showing *little* degradation is **inconclusive** — at n=1 it cannot distinguish a
small effect from none, which is the same weakness the batch arm has and the reason that finding is recorded as
*probable* rather than *confirmed*. **The asymmetry is acceptable because the confirming direction is the one
that matters:** it would put a number on something the project currently defends with judgement alone.

**And one contamination the design cannot remove:** the operator must be *told* to suppress its reads, so it
knows it is in an arm. The thinking-level arms have the identical problem. **Label it rather than pretend
otherwise**, and note that the deliverable from the suppressed arm is discarded — it is an experiment, not a
translation.

**What it feeds, and this is why it earns its place despite the limit.** It bears on **the runtime question**
— the full dictionary reads are 5.7% of the time and were measured to pay, but never against a control — and
on **the Opus 5 work**, which asks whether defensive logic written for an earlier model can be simplified.
**Neither of those can be answered by reasoning, and both are currently answered by judgement.**

## 5. What is actually wrong, grouped by what it does to the document


**168 recorded findings.** Below they are grouped by consequence. Every finding appears in exactly one
group — proved by script, not asserted — and §9 lists which.

### 5.1 Things that silently lose content — 27 findings, 6 of them the worst grade

**The pattern is always the same shape.** The English is translated correctly. The *pointer* to it, or the
container holding it, is destroyed when the English is put back. The translated text is still inside the
delivered file, and it is unreachable.

| what happened | on how many documents |
|---|---|
| A footnote's anchor deleted. The footnote is translated, present and correct, and appears on no page — 1 → 0 on one document, 2 → 0 on another **[measured]** | 2 |
| Comment anchors deleted — 28 → 14 on one document with all 28 comment bodies still present, 13 → 9 on another. Two of the four lost on the second are substantive: one carries a priced commercial term, one a live negotiating position **[measured]** | 2 |
| Untranslated source-language text delivered on **page one**, inside a Word content control the code that puts English back never writes into | 1 *(both runs of it — the batch arm is the same document)* |
| An entire 40-entry table of contents flattened — the tab characters that made it a table of contents fell from 80 to 10, and 33 of its 34 hyperlinks were destroyed, so it is no longer laid out *or* navigable **[measured]** | 1 |
| Every cross-reference in the document printed **twice**, across 42 paragraphs, because the field skeleton is kept after the number it was holding has been consumed | 1 |
| Content-bearing punctuation deleted as "noise" — a contract delivered with no closing bracket and no sentence-ending full stop in operative text | 2 |
| An untranslated auxiliary part shipped byte-identical while the delivered document still pointed at it to render a date on its cover page | 1 |
| Boundary tabs and line breaks destroyed by a single unconditional `.strip()`, so a two-column signature block starts at the left margin | 2 |
| A tracked change destroyed as the *cost* of repairing another defect, because no compliant repair existed | 1 |
| Invisible zero-width characters surviving into the delivered file, one of them making a defined term unfindable by search | 5 |

**And two things nothing can currently see at all.** A loss introduced when the document is first read apart
is invisible to every later check, because every later check compares the run's output against notes the run
itself wrote at that moment. The skill documents this class in its own text — a past bug that cost **45
paragraphs and 1,547 characters including payment-milestone and finance-party-consent provisions** — so it
is a class that has already cost real content, not a hypothesis. And a delivered file that fails its own
integrity test prints a warning and exits successfully, leaving a possibly-unopenable document at the
delivery path.

### 5.2 Things that make the document look wrong on the page — 27 findings

**Emphasis reaches a word three different ways and the pipeline understands one of them.** A word can be
bold because its own run says so, because a *character style* says so, or because a *paragraph style* says
so. Only the first is read. And it is worse than "not carried forward": when the English is put back, the
code writes an explicit **bold-off** instruction on every run it thinks is not bold — 0 such instructions in
one source document, **694** in the delivered version **[measured]** — so style-borne bold is actively
switched off, everywhere, silently.

**The template for a rebuilt paragraph is the odd run out.** The formatting for every rebuilt run is copied
from the first run in the paragraph that carries *explicit* formatting — and a run carries explicit
formatting precisely because it differs from the rest. So a highlight marking one negotiated phrase can end
up marking an entire clause heading, which in a live negotiation draft asserts something the drafter never
asserted. The same mechanism made small capitals spread from a party's name to its capacity phrase — and the
counts *fell* while the affected text *grew*, so a count-based check reports a loss where there is a spread.
**[measured]**

**Signature blocks and layout are four mechanisms acting on the same eight lines**, which is why fixing one
leaves the block wrong: leading tab runs cannot position a line that got longer; there are no tab stops at
all to fall back on; a full-width padding character was replaced by an ordinary space, giving about a quarter
of the intended width; and a flattened tab made the operator author a colon where a column break belonged.

**Two more layout devices preserved in form and destroyed in function.** Three empty paragraphs a drafter
used as a hand-made page break survive exactly and now sit as a gap in the middle of a page. Justified text
ending in a manual line break was stretched to **91.8 points** of word spacing on page one of
Guarantee (Polish), against the source's worst of 31.1. **[measured]**

**And a mandatory tidy-up script destroys correct work.** Isolated by measurement rather than inferred — the
working directory happened to keep the file from immediately before the script ran — that one pass destroyed
**38 italic spans**, about twenty of which were italicised cross-reference titles, i.e. an entire drafting
convention, document-wide. On another document it imposed a page break the source did not have and produced
a **blank page** in a delivered contract. **[measured]**

**The unifying rule, and it is the register's most repeated lesson:** the pipeline preserves form as
**counts and flags**, never as **effects**. That is true of run properties, tab characters, padding widths,
empty-paragraph page breaks and manual line breaks alike. Preserving *how many* there are does not preserve
*what they do* once the English is 30% longer than the source.

### 5.3 Things that say it worked when it did not — 44 findings

**The strictest check compares bags of words.** No order, no punctuation, not even a count — so a word can
be deleted and the check still passes, as long as the same word occurs somewhere else in the paragraph.
Proved: the tidy-up script deleted a word and the check immediately afterwards reported *"required tokens =
8813, present = 8813, missing = 0"*. It also polices only words that went **missing**, never words that
**appeared**, which is why 42 duplicated cross-references passed it twice. **[measured]**

**The mandatory quality check cannot fail the run.** It never sets an exit code, and the end-of-pipeline
audit branches on that exit code with a code comment asserting the opposite. Observed on three documents: on
one, the audit printed *"[PASS] Step 9 — quality_check.py exited 0 (no issues)"* minutes after the check itself
printed *"\*\*\* FAILED: 32 issues must be resolved \*\*\*"*. **One line fixes it.** This is also the
project's strongest single result: two methods with nothing in common — eleven graded documents on one side,
one cold read of the code on the other — reached the same mechanism and both ranked it first for repair.

**Three more in the same family, each independent of the others.** A delivered file that fails its own
integrity test exits successfully. Omitting one optional-looking flag skips a check the manual lists as
unconditional. And a rule in the always-loaded file describes a coverage gate that **does not exist** — the
only coverage check in the whole package runs after the operator has been told the document is ready.

**Nothing in the 198 files exists whose purpose is to make a check fail.** No test, no fixture, no seeded
defect, no self-test. So no reader — and no one on this project — can confirm that any of the thirteen
executable checks fires at all. That is why a corrupt-deliverable path could sit in shipped code
indefinitely: **a check that never fires looks exactly like a check that passed.**

**And the checks that do fire cry wolf.** On one document two checks produced nine warnings, nine of them
false, and zero true findings — while a prompt-side rule with no script behind it caught two real errors.
Five false-positive classes are documented, and the skill's own drafting convention *guarantees* one of them
fires on every well-drafted continental contract. The harm is not the noise; it is that it trains the
operator to skim the one block whose job is to report genuinely dropped content.

**Language detection is guesswork that prints CLEAN.** On a document in a language the skill does not
support, four scripts each auto-detected the language, produced **three different wrong answers**, and every
one printed CLEAN or PASSED. The operator's formulation is the one to keep: *the safety net does not degrade
to nothing, it degrades to a confident wrong answer* — which is worse than no check, because the operator is
told the document is clean.

**The outside reader scored this layer highest of all.** Given the package and nothing else, a competent
independent reviewer gave the verification layer its best structural score and called it *"the criterion the
artefact is strongest on"* — because the checks are genuinely unarguable: they run as separate programs and
raise rather than return, so they cannot be satisfied by an assertion. Every word of that is true. And this
register has 28 findings establishing that those same checks are blind to the losses that matter.
**Unarguable and discerning are different properties, and the skill claims only the first while reading as
though it had both.**

### 5.4 Things that make the skill hard to keep correct — 30 findings

**Two complete trees are maintained by hand, and the default one is the degraded one.** Not a spelling
difference: the UK package — the one most users install — runs **37 spelling rules where the US package runs
60, and 34 where the US runs 91**; one tidy-up function takes a variant argument in one tree and hardcodes
the UK answer in the other, so a UK-package user who follows the skill's own documented switch to US English
gets US spelling and UK cross-references; and one blocking rule's pattern cannot see the other variant's
spelling of the phrase it blocks. **[measured]** A semantic error in the always-loaded file — two verbs
swapped, so the sentence instructs the reader to do the two things it means to forbid — was hand-corrected
in one tree and never in the other. **And nothing anywhere claims to keep the two in parity**, which is the
absence that permits all of it.

**Four capabilities are implemented thirteen times, and every disagreement between copies is already logged
as a defect.** Four independent source-language detectors, four remnant scanners, three readers of bold from
the XML, two spelling tables that have drifted apart. There is no shared library. **[measured]** The control
that proves the point is the opposite case: there is exactly **one** word tokeniser, which is why the
bags-of-words defect — the master cause of the whole checking cluster — is a one-place fix.

**The dictionaries' prohibition column barely exists in the layer the instructions lean on hardest.** Five
separate mandatory instructions treat the sub-dictionaries' *Avoid* columns as binding blocklists. That
column appears in **6 of 1,656** sub-dictionary tables, and 134 of the 154 files contain the word *Avoid*
nowhere at all. **[measured]** The cross-language reference layer, by contrast, carries it in 180 of 184
tables. **This is the cause the register previously had only the consequences of** — the compliance script
missing entries, and its prescribed remedy pointing the operator at rows that do not exist.

**Three files per tree sit past the only install-truncation position ever observed**, including the
always-loaded file, and **178 of 198 files have no integrity check at all** — 89.9% of files and 85.8% of
bytes. **[measured]** The detection did not degrade; it was rolled out to all twenty scripts and never
extended to the 85% of the package that carries the translation knowledge. The size discipline that
protected the largest script was silently abandoned when the comparison switched to a number nobody had
observed.

**And what degrades across a multi-document session is the policing, not the translation.** Three documents
in one session, the third a controlled repeat of an earlier single run: quality, terminology and consistency
scored 9/9/9 on all three and were *identical* between the two runs of the same document. Every point the
third lost, it lost to defects the first run had noticed and repaired outside the pipeline. **[measured]**
**So the conclusion is an argument for fixing the defects, not for a rule about batching** — fix them and
batch position stops mattering, because there is nothing left to rescue.

### 5.5 Places where the manual is simply wrong — 43 findings, and it is now the largest

**Three mandatory requirements cannot be met at all.** One requires a check to report zero issues while two
other mandatory rules forbid both available ways to get there. One requires the operator to verify that no
tracked changes are visible in a document containing a revision type the skill has no concept of and no
script can remove. One requires a dictionary's preferred wording whose required adjacent data sits in a
different paragraph, which another mandatory rule forbids merging. In each case the operator's only options
were to disobey an instruction or to ship against one.

**The last thing read before delivery tells the operator to destroy the work.** The final visual checklist
says the delivered document should have *"No tracked changes visible … no revision marks, and track changes OFF"*. On a redline
— and half the pipeline exists for redlines — following that literally means stripping the revisions the
skill just worked to translate correctly. It plainly *means* "no spurious annotations", and it says the
opposite, at the worst possible moment. **One line.**

**The most load-bearing command in the setup step is wrong as written**, and it is the only step that does
real work on the one document class that needs it. It printed a usage screen and converted nothing.

**The gate that decides whether a file is safe to modify has a circular instruction and an irreversible
failure mode.** The compliance checkbox requires the operator to confirm it inspected the script's output
*and did not run it on a redline* — and the only way to obtain that output is to run it. On one document
that would have flattened a live negotiation redline carrying a six-figure price reduction. The operator
refused and replicated the check by hand. **The code is genuinely good; the defect is entirely in the
instruction wrapped around it** — which is why an outside reader praised it.

**The count of automatic checks is stated five different ways** across the package — four, a different four,
five, three, and the code invokes five — while a pre-step checkpoint makes naming them from memory a
condition for proceeding. **So the self-check the skill sets as a hard stop cannot be passed from the file it
points at.**

**One sentence of one step document is wrong twice, in opposite directions**, each capable of visibly
damaging output: it says tabs are preserved (they are not, inside a text-bearing run) and that the extractor
does not insert newline characters (it does, and expects them back). An operator who trusted the document
over the code would have collapsed two address blocks and four amount clauses into running text.

**Nothing tells the operator that a check can be wrong about *what it is checking*, and the wording actively
discourages the thought.** The reconciling rule already exists in the project charter — *never alter a
source-faithful translation to satisfy a linter; if a check conflicts with fidelity, fidelity wins and the
check gets fixed* — and it is not surfaced anywhere the operator meets a check. **This is the cheapest fix
in the project and it is what makes every scoping defect elsewhere expensive instead of cheap.**

**And nothing anywhere addresses the person who receives the document.** Every message in the package speaks
to the operator: re-author the file, re-install the skill, fix and re-run. The only channel to the reader is
the operator hand-writing "delivery notes", whose required content is specified nowhere. Nothing states that
the delivered file exists only if the run finished — so a partial document is indistinguishable from a
finished one to the person signing it.

**And the same blindness pointed at the person who INSTALLS it.** *(Added 2026-08-05 by the audit, which
found that the six findings recorded at the end of that session had never been described here — only counted.
See the note below.)* **The package cannot say what it is.** There is no version field, no file list and no

detect a partial install by comparing what arrived against what should have — which is why the truncation work

a rubric that is not in the package and is not published — this project's own private grading instrument,
named by criterion number in a public artefact.

**Two instructions that cannot be obeyed as written, and they compound each other.** *(Added 2026-08-05 by
the disposal check described in §12; both were confirmed against the sealed package rather than taken from the
report that found them.)* **Repair is unbounded.** Two instructions tell the operator to keep going until a
check goes green — *"Re-run the compliance scan until it exits 0"* and *"fix, then re-run Steps 5-9 in

**And the five Hard Rules are announced as enforced when three of them are not — at least not where they say
they are.** The block's own header reads *"Hard rules. Non-negotiable. Enforced by the skill's gates."*
Measured against the twenty scripts: **rules 2 and 5 name their mechanism and have it, at the step they name.
Rule 1 (one document at a time) and rule 4 (read every paragraph's complete text) have no mechanism at all**
— and rule 4 cannot have one, because no script can know what the model read. **And rule 3's gate does not

after the operator has already been told the document is ready. **[measured]** **So the strongest assurance
sentence in the always-loaded file is true of two of the five rules beneath it.** This is a claim defect rather than an enforcement defect: the fix is to say which rules the gates
enforce and which rest on the operator, not to build a gate for something ungateable.

**Two more wrong instructions in the same set.** One explains a real refusal by attributing a property to a
mechanism that has no such property — the file it describes contains no permission handling of any kind, so
the stated reason is invented. **[measured]** The other is a mandatory rule whose cross-reference points at
the wrong rule, in the always-loaded file, which is exactly where an operator goes to resolve doubt.

### Option 1 — Stop the code that puts English back from deleting what it does not recognise

**What it is.** When the English goes back into the document, each paragraph's contents are sorted into
keep / rebuild / delete. That sorting is wrong in four separable ways: the keep-list has seven entries and

protected thing loses the protected thing without the keep-list ever being consulted; hyperlinks are deleted

the way out.

### Option 2 — Check the delivered document against the **original**, not against notes the run wrote itself

**What it is, and it is bigger than it was a week ago.** Every check in the package reads either the run's
own notes file — so it cannot see what happened after that file was written — or word tokens, so it cannot
see order, punctuation, whitespace or formatting. There are **three** blind spots with that one cause, not
one, and this is the change the last week made to Step B's shape:

1. **The conversion**, at the very first step. A legacy Word file is converted and every later step measures
   against the converted copy, so a loss introduced by the conversion is invisible to everything.
2. **The reading-apart**, at the second step. If the text was never captured, the notes never contained it,
   so nothing downstream can know it existed. **The planned fix for (3) does not close this** — it compares
   against the declared translations, which come from those same notes.
3. **After the English goes back.** The proposal already on record: reconstruct the accept-all and
   reject-all readings **from the finished document** and diff them against what was declared.

**Plus four things that make the checks capable of being trusted at all.** Give the mandatory quality check
an exit code. Make a failed integrity test on the delivered file stop the run instead of printing a warning.
Make the skipped-by-omitting-a-flag check refuse instead of warn. And **build one test input per check that
violates that check's stated pass condition**, because nothing in the package can currently demonstrate that
any check fires.

> **This option cannot be finished without decision 3** (see the table above and §11). Making the checks
> discerning converts **eighteen** currently-silent findings into runs that cannot finish, because those
> eighteen have no compliant repair. Everything else in this option is unaffected.

**One refinement that came out of trying to refute this** (§12, refutation attempt 1). "Compare the delivered text against
the original" is not decidable as written, because the two are in different languages. The decidable form is
**same-language**: compare the original document's text against what the reading-apart step captured — exact,
cheap, deterministic, and precisely the check that would have caught the truncation bug the skill documents
against itself. The delivered file then needs a **structural** correspondence check (paragraph counts,
reference counts, per-paragraph text-element counts), not a text one.

**What actually changes — and one prescription that was missing until the prescription check found it.**

**The step the skill calls its own single most common failure mode is checked by nothing.** Step 3 — the
mandatory end-to-end dictionary read — leaves no artefact: no file, no state entry, nothing downstream that
could distinguish a full read from a skim. Completion rests entirely on the executor ticking a box, in the
same file that says *"the single most common failure mode of this skill is partial lexicon reading followed by
calque drift"*.

**And a coverage gap the checking layer has never been measured against: a numbered pipeline step with no
check anywhere.** *(Added 2026-08-05 by the disposal check in §12, then confirmed in the sealed package.)* Step
4c tells the operator to find every broken cross-reference marker in the notes and repair it in the English
field. **The marker string appears in exactly one file in the whole package — the step document that
describes it — and in none of the twenty scripts.** **[measured]** So there is nothing to give a failing input
to, and nothing that would notice if the step were skipped entirely. **The point generalises past this one
step, which is why it belongs here rather than in a list of small fixes:** the thirteen executable checks were
never derived from the fifteen steps, so **the question "which numbered steps have no check at all?" has never
been asked.** Slice 1 should answer it once, as a table, before building the failing inputs — otherwise the
harness proves the checks that exist can fire and says nothing about the steps that have none.

**Honest limit, conceded rather than papered over: no mechanism can confirm that an agent read a file rather
than skimmed it.** What *is* actionable is our own harness lesson turned on the skill — our read gate has the
identical defect, recorded as *"the read gate verifies ENDPOINTS, not reading"*, because it asks for a byte
count and a last line that the operator already knows from the previous document. **The remedy is the same in
both places: demand something POSITION-DEPENDENT — a quoted line at an offset the executor cannot predict.**
That converts an attestation into weak evidence, which is a real improvement over an assertion.

**Three implementation specifics from the blind review's own report, which this analysis had not carried.**
They matter because two of them change what "make the checks able to fail" actually means:

- **The WARN contract must become distinguishable, not merely non-zero.** The documented contract is `0` PASS
  / `1` WARN / `2` FAIL; the code returns `1 if strict else 0`, so **WARN is indistinguishable from PASS**.
  The report's prescription is exact: return **2 if strict else 1**, which matches the documented contract
  rather than inventing a third one.
- **The repack must set an explicit success code**, not merely avoid setting a failure one — its `__main__`
  never sets a code at all.
- **The integrity guard must move above `__main__`**, not merely be called: it currently sits below it, so on
  the only path that exists it fires after everything has already run.

**And the report's cost estimate for this slice is under an hour**, *"including a run to confirm nothing
downstream was relying on the always-zero exit"* — with the risk named honestly as *"surfacing latent QC
failures that were previously invisible — which is the point."*

### Option 3 — Say what the formatting actually **is**, instead of guessing

**What it is.** Today the reading-apart step reports a run's own bold and italic flags and nothing else — no
character styles, no style inheritance, no highlight, no small capitals, no underline that can be asked for
back. And the writing-back step copies one formatting template onto every rebuilt run in the paragraph. The
change: **compute each run's effective formatting** by resolving the style chain (paragraph style and its
parents, document defaults, character styles, table styles), carry a reference from each English span back to
the source run it came from, and derive properties **per span** instead of copying a template.

> **Corrected 2026-08-05: this option no longer claims the layout group.** §12's fifth refutation attempt
> showed that A3's mapping of those findings to the formatting keystone is a *cause* map, not a *fix* map —
> every one of them names the golden rule as the blocker. They now have **option 11**, and only the
> line-height finding stays here, because its mitigation genuinely *is* this computation.

**Two things make this the most ambitious option and the hardest to decompose.** The explicit bold-off
instructions cannot be removed before the computation exists — remove them first and one document's entire
body renders bold. And a wrong style computation is **worse than today's honest guess**, because the operator
will stop checking. That is why it needs option 2's comparison underneath it.

**One thing settled by experiment, which is why a cheaper version will not do.** On one document an operator
built a purpose-built style resolver, got every heading right and the hardest intra-paragraph case right, and
**still lost the same two defined terms**, because their bold came from a character style its tool never
examined. **A partial resolver is measured insufficient.**

**What actually changes beyond the formatting — two prescriptions this option owns and did not carry.**

**(a) THE DEFINITIONS DETECTOR — and this is the cluster behind the production failure that started the
project.** A delivered client deed's definitions were never reordered, because the detector locked onto a
false-positive cluster **146 paragraphs before** the real definitions block. The register's own conclusion is
not "patch the heuristic":

> **The detection approach is what is failing, not each individual heuristic.** Every past fix added another
> negative rule to a stop-list, and the next document defeated it with a phrase nobody had thought of. **No
> finite list of rejected prefixes can work, because the noise is document-specific.** The detector already
> carries scar tissue from three earlier post-mortems.

**Three live mechanisms, all measured:** both detectors **return on the first match**, so the architecture
assumes exactly one definitions section per document; the heading fallback is anchored end-to-end, so
*Certain Definitions*, *Additional Definitions* and *Interpretation and Definitions* all miss while
*Definitions and Interpretation* passes; and the false-positive cluster wins.

**The register weighs TWO structural alternatives, and the first version of this option showed only one —
the same failure as Option 4's three shapes, so both are set out here.**

**Alternative 1 — anchor on the SECTION rather than on the paragraph shape.** Find the definitions *clause*
first — by heading, by outline level, or by **the density of `"Term" means` predicates in a window** — then
take the definitions inside it. The production document had **32 unambiguous `"Term" means` paragraphs in a
43-paragraph span**; a density scan finds that instantly and *"would never mistake three agenda pointers 160
paragraphs earlier for it"*. **It needs no schema change, so it is available even if this option is deferred**
— which is its real advantage.

**Alternative 2 — let the operator DECLARE it, which is what this option makes possible.** Preferred, for the
reason below.

**Why alternative 2 is the recommendation.** The register states it plainly:
*"Detection is only necessary because the pipeline throws away something it already knew."* The operator has
just authored every definition at Step 4. **So the prescription is a declared field in the notes — a
`definitions_range`, or a `role` marker on those paragraphs — which is a data-contract change and therefore
exactly this option's business.** A3 says the same from the other side: this option closes the definitions
guessing **if** the data contract gains a role or range field.

**With three conditions, because a declared field does not retire the detector on its own:**

1. **The detector stays as a FALLBACK for notes that carry no declared range**, and in that mode it must
   **scan for multiple candidate sections and report every one** rather than returning the first — which alone
   fixes the single-section assumption and makes the lock-on *visible instead of silent*.
2. **It must FAIL LOUDLY.** It has **two consumers** — the reorder step and the only formatting gate in the
   pipeline — and both are silent on failure, so each of its four documented misses also left that gate inert
   **and reporting clean**. An independent reader praised the sharing as good de-duplication and was right;
   the answer is not to duplicate the detector but to make it fail loudly.
3. **The term-sanity guard must survive.** When the detector was wrong on the production deed, that guard
   refused to reorder and turned a corruption into a no-op. It is the best example in the project of
   defence-in-depth paying for itself. **Do not weaken it while fixing the layer above it.**

**(b) FIXED LINE HEIGHT — a latent clipping hazard this option creates the conditions for.** One source sets
a fixed 14pt line height on 238 paragraphs; anything taller than the fixed height is **clipped**. This option
is what computes and emits sizes, and the pipeline is already documented changing a run's size — a value
inheriting its label's larger size on another document. **On any paragraph carrying both, glyphs would be
clipped and the text would ship unreadable, past every gate, because no check looks at line geometry at all.**
Prescription: **when the source uses a fixed line height, refuse to emit a larger size than the source run
carried, or warn.** Neither document exhibits both today, which is why nothing has caught it.

### Option 11 — Layout: see it and say so, or open one narrow lever

**Added 2026-08-05.** It was missing, and its absence was the real gap: **the only proposal that would repair
Wouter's own named signature-block complaint was sitting in §11 as a question, with no costs beside it and
nothing to compare it against.**

**What the layout group is.** Six findings about **where things sit on the page**. English is about 30% longer
than the source languages. Drafters position things with devices that do not stretch — a tab character to push
a name into a right-hand column, three empty paragraphs to force the next clause onto a new page, full-width
spaces as padding, a manual line break. **The pipeline preserves how many of each there are, perfectly, and
cannot preserve what they do once the text is longer.** Measured: four lines that sit right-of-centre in the
source sit at the **left margin** in the delivery, with the signatory's name separated from his title · a
clause heading that opened page 4 now sits mid-page · eleven full-width padding spaces became eleven ordinary
ones, about a quarter of the intended width · justified text stretched to **91.8 points** of word spacing on
page one of Guarantee (Polish), against the source's worst of 31.1. **[measured]**

**Why it is its own option rather than part of the formatting work.** Because **every one of these could be
fixed and every fix is forbidden by the golden rule** — the rule that the pipeline replaces only the *text*
inside existing runs and never touches structure or paragraph properties. Repairing a signature block means
adding real tab stops to the paragraph properties; repairing the page break means converting three empty
paragraphs into a real page-break instruction. Both are structural edits. **That is why the formatting option
does not close them, and it is decision 4.**

**6 findings, three of them visible defects.** **Two shapes, and they are genuinely different products.**

**11a — see it and say so.** Render both documents, compare, and flag any layout device whose **rendered
position** changed. Do not repair it; route it through option 5's disclosure channel so the operator records
it and the reader is told.

**11b — one narrow, declared lever.** Allow the pipeline exactly two structural edits, and only where a
rendered comparison proves the effect was lost: convert leading-tab positioning into real tab stops, and
convert an empty-paragraph run into a real page break. Always disclosed, never silent.

## 8. Glossary — each term defined once


| term | in one sentence |
|---|---|
| **`.docx`** | A Word file is a zip archive of XML documents; the main one holds the body text |
| **OOXML** | The XML language inside a `.docx` |
| **run** | A stretch of text inside a paragraph sharing one set of formatting; making three words bold splits one run into three |
| **paragraph properties / run properties** | The formatting attached to a whole paragraph, or to one run |
| **style / the style cascade** | Named formatting a paragraph or run can point at instead of spelling it out; styles inherit from parent styles and from document defaults, so a word's real appearance may be stated nowhere on the word itself |
| **character style** | A style applied to a *run* rather than a paragraph — one of the three routes by which a word can be bold, and the one the pipeline cannot see |
| **auxiliary parts** | The other XML documents in the archive: headers, footers, footnotes, endnotes, comments, numbering, and a glossary part the skill never lists |
| **anchor / reference** | The marker in the body text that points at a footnote or comment; delete it and the footnote still exists in the file but appears on no page |
| **tracked changes** | Word's record of insertions and deletions, which makes a document readable two ways — as if every change were accepted, and as if every one were rejected |
| **zero-width space** | An invisible character the operator legitimately uses to stop a script gluing two words together; it survives a whitespace strip because it does not count as whitespace, and it must not survive into the delivered file |
| **the notes file** | The intermediate file the pipeline writes when it reads the document apart, holding each paragraph's source text, the English, and the formatting spans; nearly every check compares against this rather than against the original |
| **the golden rule** | The pipeline never rewrites the document — it replaces only the *text* inside existing runs, leaving styles, numbering and structure untouched. This is why formatting survives at all, and it is also what makes the layout group unfixable |
| **gate / check** | A program that inspects the work and refuses to continue if it fails. A gate firing is the skill working, not an error |
| **exit code** | The number a program returns when it finishes; zero conventionally means success. Several of this skill's checks report failures in their output and still return zero |
| **calque** | A translation that copies the source language's construction rather than using the settled English term |
| **dictionaries: references and sub-dictionaries** | Two layers — 15 cross-language English domain references, and 154 per-language files (11 languages × 14 domains) |
| **furniture** | The formulaic apparatus of an instrument rather than its subject matter: title block, execution line, attestation, signature labels, section symbols, cross-reference conventions |
| **variant** | The two published builds, UK English (default) and US English |
| **fixture** | A small test document, built on purpose to exercise one thing |
| **negative fixture** | A test input built to make a check **fail**, which is how you prove the check works at all |
| **frozen intermediate** | A notes file kept from a completed run, so the mechanical half of the pipeline can be re-run and compared byte for byte without a model |
| **deterministic** | Same input, same output, every time — which is what makes byte comparison a valid test |
| **byte comparison** | Checking two files are identical to the last character, rather than judging whether they look the same |
| **branch / merge / squash-merge** | A branch is a parallel line of work; merging brings it into the main line; squash-merging collapses it to a single entry in the history |
| **`git bisect`** | Automatically finding which change introduced a fault, by testing halfway points — it needs a cheap, repeatable pass/fail test, which is why the harness comes first |
| **regression** | Something that used to work and no longer does |
| **integrity sentinel** | A marker at the end of a file, plus code that checks it is there, so a file cut short during installation announces itself |
| **manifest** | A list of every file in the package with its checksum — the only way a file that cannot check itself can be checked |
