## How to read this

- **Origin** — `log` = the operator's forensic record; `grade` = the independent A2 grading;
  `WvdB` = Wouter's own review / production use of the published skill; `probe` = the C3
  conversion measurement; `repro` = the failure re-run and confirmed here from the delivered file;
  `code` = read directly out of the rev44 published trees, with no document involved.
- **Sev** — CRITICAL (content lost or corrupted), HIGH (visible defect), MED, LOW, POS (positive
  finding worth preserving).
- **Cluster** — the root-cause group. **This is the column that matters.**
- A finding seen on several documents is **one row**, with all doc-ids listed. Recurrence across
  documents is evidence of generality, which is exactly what Step B needs.

### What the letters mean — the plain-English key

*Added 2026-07-31 at Wouter's request. The letters had been in use since the register was created and
never spelled out. **The full version, with the vocabulary explained, is in `A3-STRUCTURAL-ANALYSIS.md`.***

**A cluster is a group of findings that share one ROOT CAUSE** — not one symptom and not one document.
That is the whole point of the letters: one structural fix may close several findings that look unrelated.

| letter | in one line |
|---|---|
| **A** | putting the English back **rebuilds each paragraph's runs from scratch** and loses what they cannot carry — deleted markers and tabs on one side, undescribable formatting on the other |
| **B** | a **mandatory end-of-pipeline clean-up script edits correct English into something else** |
| **C** | the **automatic checks pass broken documents**, because of what they compare — the strictest compares *sets of words* |
| **D** | **English is longer**, and tabs, padding spaces and blank paragraphs do not stretch with it |
| **E** | the dictionaries are organised **by domain × language**, so the entry needed is often in no file the operator was told to read — or in no file at all |
| **F** | **rules inside the skill that contradict each other or are wrong**; three cannot be obeyed at all |
| **G** | **checks that cry wolf**, training the operator to skim the warning block |
| **H** | an **already-English document**, which nothing in the pipeline notices |
| **J** | an **invisible zero-width space** used as a workaround survives into the delivered file |
| **K** | **nothing tells the operator a gate can be wrong** *in scope*, and the wording discourages the thought |
| **L** | the code that finds the **definitions clause guesses, and fails silently** |
| **X** | **an outside reader was reassured by something untrue** — praise for what this register shows is broken |
| **S** | scripts **guess the source language, guess wrong, and print CLEAN** |
| **Y** | **the package tells its installer almost nothing about itself** — no version, no file list, no runtime, no way to report a fault |
| **T** | **what a multi-document session degrades** — the policing, not the translation |

**Not clusters:** `P1–P27` are **positives to preserve**; `I-1…I-16` are defects in **our own measuring
instruments**, kept apart so they can never be mistaken for skill findings *(renamed from `H-n` in July to
stop colliding with cluster H)*; and `M1, N1, O1, Q1, R1, U1, V1, W1, W2` are **single-instance findings**,
one letter each, sharing a cause with nothing else.

> **The one real trap: `D1`–`D6` are cluster-D FINDINGS and `D01`–`D11` are the eleven corpus DOCUMENTS.**
> Two digits means a document, one digit means a finding. `audit_register.py` excludes the letter `D` from
> its cross-reference check for exactly this reason.

**The letters carry no ordering and no priority** — they were allocated as causes were discovered. `I` is
skipped because `I-n` was already taken.
